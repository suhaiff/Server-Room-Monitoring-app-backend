# Independent ESP32 Test Lab

## Purpose

The Test Lab is intentionally separated from the VTAB operational dashboard. It behaves as an external ESP32 device rather than as an internal administration page.

## Data path

```text
Independent Test Lab UI (5174)
  -> Test Lab publisher API (8010)
  -> Mosquitto MQTT (1883)
  -> MQTT ingestion worker
  -> PostgreSQL / TimescaleDB commit
  -> threshold alerts and incidents
  -> AI analysis and linked results
  -> operational dashboard refresh (5173)
```

The Test Lab has no database credentials, dashboard access token or AI-service credentials. It cannot create alerts directly. It can only publish a hardware-shaped MQTT message.

## Starting locally

```powershell
python start_vtab.py
```

For the first clean retest, remove all old local Docker data and start everything with:

```powershell
python start_vtab.py --fresh
```

For later test cycles, use **Administration -> Clear all test data** in the operational dashboard. That preserves users, devices and configuration.

Open:

- Independent Test Lab: `http://localhost:5174`
- Operational dashboard: `http://localhost:5173`
- Test Lab API diagnostics: `http://localhost:8010/docs`

## Demonstration procedure

1. Keep the dashboard and Test Lab open in separate browser tabs or windows.
2. Sign into the dashboard and enable Voice Intelligence.
3. In the Test Lab, publish Nominal Operation.
4. Publish Unauthorized Access.
5. Observe the MQTT acknowledgement in the Test Lab.
6. Switch to the dashboard and confirm the database-backed door alert, incident, AI activity and voice message.
7. Publish Nominal Operation to resolve the condition.
8. Repeat with Fire Emergency and Compound Failure.

## MQTT status badge

The badge in the top-right of the Test Lab represents the simulator API's connection to Mosquitto:

- **MQTT CONNECTED** (green): the external lab can publish ESP32 packets.
- **MQTT WAITING** (red): the broker or simulator API is not yet reachable.

The simulator API now connects during startup and retries through its status checks. If the badge remains red for more than ten seconds, run:

```powershell
docker compose ps -a
docker compose logs simulator-api mosquitto --tail=100
```

Both `mosquitto` and `simulator-api` must show `Up`. Rebuild the two services after upgrading from an earlier package:

```powershell
docker compose up -d --build mosquitto simulator-api simulator-ui
```

## Physical ESP32 replacement

The physical board must publish JSON to `devices/{device_id}/telemetry` using the same payload structure generated by the independent Test Lab. No dashboard code needs to change when the simulator is replaced by hardware.

The optional random background publisher is excluded from normal startup to prevent artificial data from interfering with demonstrations. Start it only when continuous load is required:

```powershell
docker compose --profile background-simulator up simulator-background
```
